# birdnet-analyzer pulls TensorFlow; some paths exceed the default 260-char limit
# when the project lives under a long folder name (e.g. Desktop\...\Noise-Aware-...).
#
# Fix ONE of the following, then retry (after cleanup — see bottom):
#
# (1) Enable long paths (administrator PowerShell), then REBOOT:
#     New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
#       -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force
#     Or: Local Group Policy Editor → Computer Configuration → Administrative Templates
#         → System → Filesystem → "Enable Win32 long paths" → Enabled
#
# (2) Shorten the path: clone or copy the repo to something like C:\src\bnp\
#     (spaces + long names make the problem worse.)
#
# (3) Skip installing BirdNET inside this .venv: create a venv at a SHORT path only for BirdNET, e.g.
#       C:\venvs\birdnet\Scripts\python.exe -m pip install -r requirements-birdnet-analyzer.txt
#     Then set BIRDNET_PYTHON or birdnet_python in birdnet_integration/experiment_config.yaml
#     to that interpreter. The core pipeline can keep using its own .venv.
#
# After a failed TensorFlow install, clean before retrying:
#     pip uninstall tensorflow tensorflow-intel birdnet-analyzer -y
# ---------------------------------------------------------------------------
